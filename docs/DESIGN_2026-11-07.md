## 3. 完成済み書式を守る境界

v2.1.2の初期書式は、描画枠12×9 cm、英数字Times New Roman 24 pt、日本語凡例は明朝体、上部2列凡例、曲線幅2.5 pt。単独図は黒、比較図は既存の配色順。物理ポイントを使った寸法計算、0を中心とした軸・整数目盛り、微小オーバーシュートの表示上の扱いも維持する。

ただし、既存図に利用者が別の書式を設定していれば、その現在値を優先する。24 ptや12×9 cmを再読込時に強制適用しない。

処理の境界は次のようにする。

- **新しく作図する**：既存のHMH_Color、HMH_Layout、HMH_NewGraphAxesを利用する。
- **保存図を開く**：保存した編集状態を復元する。初期書式・自動範囲・凡例再配置を適用しない。
- **フォルダを作る／名前を変える／移動する**：管理台帳だけを更新する。図形・軸・線・文字・凡例へ書き込まない。
- **矢印を動かす**：選択した矢印の始点・終点だけを更新する。
- **既存の書式設定を明示的に使う**：従来どおり適用し、その結果を図の編集状態へ記録する。

`HMH_Layout`、`HMH_ApplyAxes`の計算本体や配色を管理機能追加のために書き換えない。必要なID解決と保存通知は呼び出し側か小さな接続関数に置く。

## 4. 階層フォルダと変更されないID

推奨は **管理画面の自由な階層と、Waveを置く内部保存先を分離する構成**。ツリー内でフォルダ・データ・図を移動しても、Waveの物理パスを動かさない。これにより、既存のグラフや式の参照を守りやすい。

これはExperiment内の管理機能であり、Windows上のフォルダ作成やVSM原本の移動とは別の操作になる。Igor標準Data Browserに同じ物理階層を再現する要件は現時点でないため、そこまでの移動は実装しない。

|対象|永続情報|
|---|---|
|フォルダ|folderUID、parentUID、表示名、兄弟間の順序|
|測定|datasetUID、folderUID、表示名、内部Data Folderの所在、元ファイル情報、旧一覧との対応|
|グラフ|graphUID、folderUID、表示名、traceとdatasetUIDの対応、編集状態、開閉状態|
|矢印|arrowUID、graphUID、描画レイヤー・グループ、座標系、始点・終点、既存スタイル|

IDは表示名・一覧行・外部ファイル名から作らず、一度付けたら名前変更・移動でも維持する。採番時には衝突検査を行う。表示行から必ずIDへ変換し、ツリーの行番号を測定番号として扱わない。

新規管理領域の案：

```text
root:MHApp:
  Run0: ...                 既存の測定は元の所在を維持
  Figure: ...               現行の新規図向け設定を維持
  Axes: ...                 現行の軸編集用作業領域を維持
  Manager:
    schemaVersion
    Folders: ...            UID、親UID、表示名、順序
    Datasets: ...           UID、所属、実体の所在、旧index
    Graphs:
      g_<UID>:
        metadata
        traceBindings
        recreation
        waveBindings
        Arrows: ...
    UI: ...                 展開状態、選択ID、取込先
  Data:
    d_<UID>: ...            新規測定用の固定内部名
```

表はIgorのText Wave・数値Wave・String/Variableで保持する。行番号や実行中のWave参照だけを保存形式にしない。schemaVersionはアプリの版番号から独立させる。

階層移動では、移動先がフォルダか、親が存在するか、自分自身・子孫への移動で循環しないかを先に検証する。同じ親の中の同名は重複を知らせ、別の親では同名を許す。日本語や空白は表示名として保持し、Igorの物理名の制約を表示名へ押し付けない。

複数の表を更新する操作は、作業用コピーで整合性を確認してから確定する。中断時は元の所属と一覧へ戻し、部分移動を残さない。

## 5. 管理画面

既存の図と書式設定画面を保ち、新しい「データ・グラフ管理」画面を追加する。

- 左：開閉できる階層ツリー。フォルダ・測定・グラフをラベルと記号で区別する。
- 右：選択した項目の情報。グラフでは使用した測定一覧、測定ではそれを使う図の一覧を表示する。
- 操作：「フォルダを作成」「名前を変更」「移動先を選ぶ」「このフォルダにVSMを追加」「選択した図を開く」「矢印の位置を調整」。
- 比較用チェックはdatasetUIDで保持し、展開・並べ替え・移動で別測定へ移らない。フォルダ行やグラフ行を測定として数えない。
- 初期実装では移動先選択を確実に動かす。ドラッグ移動を追加する場合も同じ移動処理を使う。

取込ボタンを押した時点のfolderUIDを固定し、複数ファイルを順に取り込む。途中で表示選択が変わっても取込先が変わらない。成功分と失敗分を分かる形で示す。

グラフのウィンドウ内部名と管理用の表示名も分ける。窓名が変わってもgraphUIDで照合し、`MH_*`という名前の一致だけに依存しない。

## 6. グラフと測定の関連・編集状態

1つのグラフに複数の測定が使われるため、対応を単一のファイルパスで保存しない。traceごとに、測定ID、X/YのWaveの役割、重ね描き順、軸への割当を保存する。同じ測定を複数回描くケースもtrace単位で区別する。

再表示は次の順序とする。

1. 同じgraphUIDの窓が開いていれば、その現在の窓を前面に出す。古い保存状態を上書きしない。
2. 閉じていれば、保存した図の再構築情報とWave対応表から復元する。
3. 必要な測定が欠けていれば、その測定を明示する。似た名前の測定への差し替えや、欠けた曲線を黙って省いた図を完成扱いしない。

書式の数項目だけでなく、Igorのネイティブな再構築情報を保存する。これにより、手動変更したフォント、曲線、凡例、TextBox、軸、描画オブジェクト等を保持する設計とする。公式の `WinRecreation` はグラフ再構築情報を取得でき、options=2ではWave名をトークンに置き換えて取得できる。このトークンをその時点のWave表と対応付け、保存にはアプリ独自の測定ID・Wave役割を使用する。Igorの一時的なWave番号を永続IDとして使用しない。[公式：WinRecreation](https://docs.wavemetrics.com/igorpro/commands/winrecreation)

独自に追加されたWaveも依存表へ記録する。管理測定に属さないWaveを検出した場合は、管理範囲外の依存として保持・表示し、閉じた図の復元に必要なWaveを勝手に削除しない。

図の再構築情報は閉じた図の保存状態の正本とする。専用パネルの数値だけを正本にすると、Igor標準操作で編集した内容を失うため避ける。開いている間は実際の窓を正本とし、保存・閉じる直前に最新状態を採取する。矢印の管理表は同じ採取で同期し、復元時に古い表で二重描画しない。

保存時の同期には、固有名の関数を `SetIgorHook` で追加登録する。既存の他パッケージのhookを削除せず、0を返して後続処理を妨げない。窓のmodifiedイベントでは変更フラグだけを立て、常時再作図や全データ走査をしない。図を閉じる処理では破棄前に採取するタイミングを実機で検証する。[公式：SetIgorHook](https://docs.wavemetrics.com/igorpro/commands/setigorhook)

描画ツールモード中の採取は別途検証が必要。options=4はモードを抜けずに取得できるが、options=2とは目的が異なるため、未確認のビット合成を前提にしない。必要ならモード維持用の全文と、別途採取したWave対応表を組み合わせる。

データの表示名変更は管理画面に反映するが、既存図の手編集済み凡例を自動で作り直さない。新しい図には新しい名前を使い、既存の「見本の書式にする」等は従来どおり明示的な操作として残す。

## 7. 矢印の後編集

新しい管理矢印はIgorのDrawLineと矢印属性を持つ描画オブジェクトとして扱い、1本ずつarrowUIDに対応する名前付きグループで識別する。始点と終点を独立して変更し、線幅・色・矢印先端・描画順・レイヤーは維持する。

編集方法は、Igor標準描画ツールでの選択・端点ドラッグと、「矢印の位置」パネルでの数値入力・微小移動を用意する。パネルでは対象の矢印名とX1/Y1/X2/Y2、移動刻みを表示する。確定した編集だけを保存し、取消時は元の座標へ戻す。

座標は画面ピクセルだけで保存しない。X/Yそれぞれの座標系、参照軸、座標値を保存する。既存オブジェクトの座標系は変更せず、新規矢印は通常のbottom/left軸に結び付ける。これにより、表示倍率や画面のDPIが変わった場合にも意味のある位置を復元できる。

選択したグループだけを差し替え、UserFront/UserBackのレイヤー全消去をしない。`DrawAction`には名前付きグループの取得・削除・挿入機能がある。[公式：DrawAction](https://docs.wavemetrics.com/igorpro/commands/drawaction)

現行版に専用の矢印データはないため、既存図の矢印は利用者がIgor標準機能で追加した可能性がある。通常のDrawLine矢印は、レイヤーから取得して形・位置を変えずに管理登録する。未対応の複合図形やTagのリーダー線を通常矢印へ自動変換しない。これらも図全体の再構築情報に保持し、専用の端点編集対象にできるかは種類ごとに判定する。

## 8. 保存・再開と既存データの移行

Folders/Datasets/Graphs/Arrows/UIをExperiment内に保持し、File → Save Experimentで一緒に保存する。外部VSMは出典情報として記録し、保存済みWaveの再表示の必須条件にしない。

初回移行は以下の順序とする。

1. 初期化前のExperimentコピーと、対応する旧IPF一式・ハッシュを保存する。
2. `root:MHApp`の既存paths/names/countと実体を照合する。欠損・重複・不一致があれば勝手に補正しない。
3. 既存の測定へIDを一度だけ付ける。既存WaveやData Folderを移動・再計算しない。名前・一覧順・比較チェックも対応付ける。
4. 既存データは管理ツリーの初期フォルダへ登録する。以降は任意の階層へ移動できる。
5. 開いている既存MH図はtraceの実Wave参照を調べて関連付ける。グラフの見た目は変更せず、その時点の編集状態を登録する。
6. 過去に閉じられた図は、保存済み再構築マクロ等が存在する場合だけ取り込める。現行版に残っていない図を復元できるとは扱わない。
7. 作業用領域で整合性を確認してからschemaVersionを確定する。再度パネルを開いてもIDや測定・グラフが増えないようにする。

旧paths/namesは必要な間、互換用の派生一覧として残す。新しい台帳と二重の正本にしない。管理画面外での物理Wave/Data Folderの移動については、不整合検出と再関連付けを設計し、名前の類似による自動修復は行わない。

PXPの保存だけでは外部Procedure参照がなくなるとは限らない。今回のMH.pxpにも旧IPFの外部参照があった。新規配布は従来どおり版付き単一IPFにまとめ、Experimentと対応するIPFの組合せを記録する。旧パスへアクセスできない環境での再開も検証する。

保存hookでの採取に失敗した場合は、直前の正常な保存状態を壊さず、対象図と失敗を明示する。BeforeExperimentSaveHookの戻り値だけでExperiment保存を中止できるとは設計しない。専用の「図の状態を保存」操作も用意して復元可能な状態を確認できるようにする。[公式：保存hook](https://docs.wavemetrics.com/igorpro/advanced-topics#beforeexperimentsavehook-refnum-filenamestr-pathnamestr-filetypestr-filecreatorstr-filekind)

## 9. 実装単位と順序

次版候補はv2.2.0。v2.1.2のディレクトリや同期ファイルを上書きせず、新しい開発用コピー・作業ブランチで実装する。実装開始時にMHの管理リポジトリと基準コミットを確定する。

|順序|追加・変更するもの|完了条件|
|---|---|---|
|1|基準データ取得、`mh_store.ipf`|ID・schema・初回登録が非破壊かつ繰返し安全|
|2|`mh_tree.ipf`、取込先接続|自由階層・名称変更・移動・選択先読込が機能する|
|3|`mh_graph_store.ipf`|図と測定の対応、閉じた図の復元、手編集保持|
|4|`mh_arrow.ipf`|選択・端点調整・取消・保存復元|
|5|保存hook・再開処理・既存UIとの接続|保存直前の編集も再起動後に一致|
|6|`tools/build.py`、説明書、回帰試験|版付き単一IPFと検証結果を配布できる|

既存mainの変更は、管理画面の入口、読込完了後の登録、新規図の登録、IDからのデータ取得へ絞る。`mh_figure.ipf`の図一覧を永続台帳・図IDへ接続し、既存の書式計算は維持する。軸や書式の適用後に保存状態へ通知する接続を追加する。

## 10. 検証と受入条件

付属TEST_RESULTSには162項目合格の過去記録がある。これは2026-10-19の記録であり、今回再実行した結果ではない。特に `tests/mh_tests.ipf:307` の保存試験は `LoadData/O/Q/R` でデータを再読込し、新しい図を描いている。Igor終了後に保存図自体を復元する試験とは区別する。

追加機能の受入試験：

|対象|確認すること|
|---|---|
|原値の互換性|全Data Folder/Waveの値、型、次元、スケール・単位、次元ラベル、Note、formula、変数・文字列を比較。対応するNaNを同等とする|
|自由階層|複数段の作成、日本語・空白を含む名称、別階層の同名、名称変更、データ・フォルダ・図の移動|
|移動の整合性|循環・重複名・不正な親を拒否、中断時の元所属復帰、展開・並替後も比較対象が同じ|
|読込|選択先への複数追加、既存測定の保持、失敗時に半端な登録を残さない|
|関連付け|単独図、比較図、同じ測定の複数利用、複数図。名称・所属を変えた後も同じIDとWaveを参照|
|書式|寸法、フォント、pt、軸・桁数、色・線幅、凡例内容・位置、独自TextBoxが管理操作で変わらない|
|矢印|複数本、始点だけ／終点だけ／全体移動、数値編集とドラッグ、取消、別レイヤー、軸座標・相対座標、重複生成なし|
|図の保存|開いている図と閉じた図、手動窓名変更、手編集直後の保存、複数回の開閉で最新版を保持|
|初回移行|v2.01/v2.1.2のコピー、再初期化で重複なし、不整合を黙って修復しない|
|共存|XRD等の保存hook・標準編集を妨げず、重い再作図ループが起きない|
|外部依存|旧IPFパスと元VSMへアクセスできないコピー環境で、対応する新版IPFにより再開できる|

保存検証は **基準取得 → 新版読込前後 → 初期化後 → 別名PXPへ保存 → 専用Igorを終了 → 新しい専用Igorで開き直す → 比較** の順で行う。原本や既存Igorの実行中Experimentを検証に使わない。

書式は新規図の基準画像と、意図的に手編集した図の両方で確認する。画像だけでなく物理寸法・フォント値・軸・凡例・矢印座標も比較し、DPIによる画面丸めを数値変更と混同しない。

今回実施したのはソース・資料・過去ログの読取り、配布IPFとソースの一致確認、重複展開版の一致確認、既存プレビューの目視。コンパイル、追加機能の実装、実機操作、再起動互換性は **未確認**。設計上の方針を、動作保証や実装完了として扱わない。
